## 2. Стандарты именования заметок и аббревиатуры дисциплин (Unique Note Naming)

Все заметки лекций и практик ОБЯЗАНЫ начинаться с официальной краткой аббревиатуры дисциплины:
`<АББРЕВИАТУРА> - Лекция <N>. <Тема>.md`
`<АББРЕВИАТУРА> - Практика <N>. <Тема>.md`

### Официальный реестр аббревиатур:
| Дисциплина | Аббревиатура | Пример имени файла |
| :--- | :---: | :--- |
| Анализ данных и ИИ | `АДиИИ` | `АДиИИ - Лекция 1. Вводная пара.md` |
| Алгебра, геометрия и теория дифференциальных уравнений | `АГиТДУ` | `АГиТДУ - Лекция 1. Векторы.md` |
| Дискретная математика | `ДМ` | `ДМ - Лекция 1. Множества.md` |
| Иностранный язык | `ИнЯз` | `ИнЯз - Практика 1.md` |
| Информационные технологии и сервисы | `ИТиС` | `ИТиС - Практика 2. GitVerse.md` |
| Математика (Матанализ) | `МатАн` | `МатАн - Лекция 1. Пределы.md` |
| Основы проектной деятельности | `ОПД` | `ОПД - Лекция 1. Жизненный цикл.md` |
| Основы российской государственности | `ОРГ` | `ОРГ - Практика 1.md` |
| Прикладная физическая культура | `ПФК` | `ПФК - Лекция 1.md` |
| Программирование (Python) | `ПРОГ` | `ПРОГ - Лекция 1. Вводная.md` |

### Регламент подгонки и миграции связей (Migration & Link Integrity):
1. **Первичная стандартизация:** При первом обращении к дисциплине или обнаружении заметок старого формата (`Лекция 1.md` без аббревиатуры) агент ОБЯЗАН привести их к актуальному стандарту `<АББРЕВИАТУРА> - ...`.
2. **Строгое сохранение целостности ссылок (Zero Broken Links):**
   - При переименовании любой заметки агент обязан найти и синхронно обновить ВСЕ входящие ссылки вида `[[Старое имя]]` на `[[Новое имя]]` во всех связанных файлах:
     * В карточках понятий (`Термины/*.md`, блок `**Связи:** [[...]]`).
     * В генеральном учебнике дисциплины (`Учебник - <Дисциплина>.md`).
     * В интерактивном графе знаний (`<Дисциплина>.canvas`, свойства `file` в JSON).
     * В реестре обработанных видео (`PROCESSED_VIDEOS.md`).
   - Переименование без каскадного обновления ссылок категорически запрещено.
3. **Непрерывное соблюдение стандарта:** Любые новые заметки создаются строго по этому формату, а структура папок всегда поддерживается в актуальном виде.

## 3. Спецификация атомарных терминов (Zettelkasten)

Каждая концептуальная карточка в папке `Термины/` оформляется по строгой структуре:

```yaml
---
type: concept
tags:
  - термин
  - <subject_tag>
aliases:
  - <lowercase_alias>
subject: <Subject>
---
**<Название термина>** — <точное определение>

---
**Связи:** [[<Название лекции>]]
```

## 4. Спецификация генерального учебника (`Учебник - <Subject>.md`)

- Единый консолидированный справочник по предмету.
- Структурирован по темам и главам (не по хронологии пар).
- Содержит трансклюзии всех связанных терминов (`![[Термин]]`) и сквозные примеры.

## 5. Спецификация холста графа знаний (`.canvas`)

Файлы `.canvas` хранят JSON со схемой узлов (`nodes`) и связей (`edges`):
- **Узлы лекций / практик:** `type: "file"`, цвет `5` (синий).
- **Узлы терминов:** `type: "file"`, цвет `4` (зелёный).
- **Группа понятий:** `type: "group"`, обрамляет все термины дисциплины для поддержания визуальной чистоты.
- **Рёбра (Edges):** направлены от узла занятия к соответствующим терминам.

## 6. Спецификация YAML Frontmatter лекций и практик (Dataview Standard)

Каждая создаваемая заметка лекции или практики обязана содержать стандартизированный блок метаданных для агрегации через плагин Dataview:

```yaml
---
subject: <АББРЕВИАТУРА>
type: лекция # или практика
number: 1
date: YYYY-MM-DD
week: 40 # номер недели
tags:
  - конспект
  - <subject_tag>
---
```

## 7. Спецификация блока самопроверки (Active Recall & Exam Prep)

В конце каждой лекционной заметки агент обязан сформировать раздел для подготовки к зачётам и экзаменам. Ответы скрываются под сворачиваемый коллаут-спойлер для возможности быстрой самопроверки:

```markdown
## ❓ Вопросы для экзамена и самопроверки
1. **<Концептуальный вопрос по материалу лекции>?**
   > [!question]- Ответ
   > <Краткий, ёмкий тезисный ответ с формулой или определением>
2. **<Вопрос на понимание связи или свойства>?**
   > [!question]- Ответ
   > <Краткий тезисный ответ>
```

## 8. Спецификация трекера дедлайнов и домашних заданий (`Дедлайны и ДЗ.md`)

В корне хранилища (`Obsidian Vault/Дедлайны и ДЗ.md`) поддерживается централизованный список задач, контрольных точек и домашних заданий, озвученных преподавателями на занятиях.

При обнаружении в видеозаписи требований сдать лабораторную, домашнее задание или подготовить презентацию агент обязан добавить пункт в соответствующий блок:

```markdown
# 📅 Реестр дедлайнов и домашних заданий

## 🔴 Срочные (Ближайшие 7-14 дней)
- [ ] **<АББРЕВИАТУРА>** (до DD.MM.YYYY): <Формулировка задания>. Ссылка: [[<Заметка занятия>]]

## 🟡 Семестровые проекты и контрольные точки
- [ ] **<АББРЕВИАТУРА>** (до DD.MM.YYYY): <Формулировка задачи>. Ссылка: [[<Заметка занятия>]]

## 🟢 Выполненные задания
- [x] **<АББРЕВИАТУРА>**: <Выполненное задание> (Сдано DD.MM.YYYY)
```
